# Re-review (`--since-last`) — step 1

Read by the orchestrator only, during step 1, once the repo checkout exists. Step numbers refer to `SKILL.md`; step 8's `--since-last` anchoring rule stays there.

Your most recent submitted review on this PR (state not `PENDING`, `user` = you) gives `<last>` = its `commit_id`. Once step 1's checkout exists, if `<last>` is an ancestor of `headRefOid` (`git -C <repo root> merge-base --is-ancestor <last> <headRefOid>`), keep the full annotated diff as `<run dir>/full.diff`, annotate `git -C <repo root> diff <last> <headRefOid>` into `<run dir>/since.diff`, and replace `pr.diff` with only the PR's own files from it: write the `files` paths from `gh pr view` to `<run dir>/pr-files.txt` (one per line, with the `Write` tool), then `<skill dir>/scripts/prepare-diff.sh slice <run dir>/since.diff < <run dir>/pr-files.txt > <run dir>/pr.diff`. Without the slice, a base branch merged into the PR since `<last>` would put every file that merge changed in front of the passes. Passes then review only what changed since you last looked, while step 8 still validates anchors against `full.diff` (which also rejects merged-in base lines in a file both touched). Fall back to a normal full review, and say why in the summary, when you have no earlier review, `<last>` equals `headRefOid`, `<last>` isn't an ancestor (force-push), or the repo root is none.
